# 02 — Workflow Decomposition

## 1. Process

**Task Delay Alert Process**

هي عملية متابعة مهام العمل ومواعيد تسليمها، والتحقق من حالة كل مهمة، ثم إرسال التنبيهات المناسبة للموظفين أو المدير وفقًا لحالة المهمة.

## 2. Workflow

يتكون سير العمل من الخطوات التالية:

1. Read Tasks
2. Check Task Data
3. Evaluate Due Date
4. Check Task Status
5. Route Task
6. Send Notification
7. Update Task Record

## 3. Tasks

| **Task** | **Description** |
|---|---|
| Read Tasks | قراءة المهام المسجلة في Google Sheets. |
| Check Task Data | التحقق من توفر البيانات اللازمة لمعالجة كل مهمة. |
| Evaluate Due Date | مقارنة تاريخ التسليم بالتاريخ الحالي. |
| Check Task Status | التحقق مما إذا كانت المهمة مكتملة أو غير مكتملة. |
| Route Task | تحديد المسار المناسب بناءً على تاريخ التسليم وحالة المهمة. |
| Send Notification | إرسال إشعار إلى الموظف أو المدير حسب المسار. |
| Update Task Record | تحديث سجل المهمة لتوثيق إرسال الإشعار ومنع تكراره. |

## 4. Subtasks

### Task 1: Read Tasks

- تخزين بيانات المهام في Google Sheets.
- قراءة سجلات المهام عند تشغيل الأتمتة.
- تحديد بيانات كل مهمة، مثل اسمها والموظف المسؤول عنها وتاريخ التسليم وحالتها.

### Task 2: Check Task Data

- التحقق من وجود اسم المهمة.
- التحقق من توفر تاريخ التسليم.
- التحقق من حالة المهمة.
- التحقق من وجود البريد الإلكتروني للموظف المسؤول أو المدير حسب الإشعار المطلوب.
- تحديد السجلات التي تحتاج إلى تصحيح قبل إرسال الإشعارات.

### Task 3: Evaluate Due Date

- مقارنة تاريخ التسليم بالتاريخ الحالي.
- تحديد ما إذا كان موعد التسليم قد تجاوز التاريخ الحالي.
- عدم اعتبار المهمة متأخرة إذا كان موعدها اليوم ولم ينتهِ الموعد المحدد لها، وفق قاعدة المشروع.
- التأكد من استخدام تنسيق تاريخ موحد لتجنب أخطاء المقارنة.

### Task 4: Check Task Status

- التحقق مما إذا كانت حالة المهمة `Completed`.
- التحقق مما إذا كانت المهمة لا تزال قيد التنفيذ أو لم تُستكمل.
- فحص حقل `Alert Sent` لمعرفة ما إذا سبق إرسال تنبيه التأخير.
- فحص حقل `Completion Notified` لمعرفة ما إذا سبق إرسال إشعار اكتمال المهمة.

### Task 5: Route Task

يعتمد النظام على مسارين رئيسيين باستخدام Paths by Zapier:

**Path A — Overdue Task**

يُستخدم عندما يكون موعد التسليم قد مضى، وتكون المهمة غير مكتملة، ولم يُرسل تنبيه التأخير سابقًا.

**Path B — Completed Task**

يُستخدم عندما تصبح حالة المهمة `Completed` ولم يُرسل إشعار اكتمالها إلى المدير سابقًا.

إذا لم تستوفِ المهمة شروط أي من المسارين، فلا يُرسل إشعار جديد.

### Task 6: Send Notification

- إرسال بريد إلكتروني إلى الموظف المسؤول عند اكتشاف مهمة متأخرة.
- تضمين اسم المهمة وتاريخ التسليم في رسالة التنبيه.
- إرسال إشعار إلى المدير عند اكتمال المهمة.
- تضمين اسم المهمة وبياناتها الأساسية في إشعار الاكتمال.
- التأكد من استخدام عنوان البريد الإلكتروني الصحيح لكل مستلم.

### Task 7: Update Task Record

- تحديث حقل `Alert Sent` إلى `Yes` بعد إرسال تنبيه التأخير بنجاح.
- تحديث حقل `Completion Notified` إلى `Yes` بعد إرسال إشعار الاكتمال بنجاح.
- الاحتفاظ بحالة المهمة وتاريخ التسليم وبيانات المسؤول عنها.
- عدم تحديث حقل الإشعار إلى `Yes` إذا فشل إرسال الرسالة.

## 5. Sequence

يجب تنفيذ المهام بالترتيب التالي:

Read Tasks → Check Task Data → Evaluate Due Date → Check Task Status → Route Task → Send Notification → Update Task Record

لا يمكن إرسال الإشعار قبل التحقق من حالة المهمة وتاريخ التسليم والتأكد من استيفاء شروط المسار المناسب.

## 6. Dependencies

| **Task** | **Depends On** |
|---|---|
| Check Task Data | Read Tasks |
| Evaluate Due Date | Check Task Data |
| Check Task Status | Check Task Data |
| Route Task | Evaluate Due Date, Check Task Status |
| Send Notification | Route Task |
| Update Task Record | Send Notification |

## Expected Outcome

تحديد خطوات متابعة المهام وترتيبها واعتماد بعضها على بعض، وتوضيح شروط كل مسار قبل تحويل سير العمل إلى نظام أتمتة باستخدام Zapier وGoogle Sheets وGmail.
